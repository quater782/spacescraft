# `src/` 实现规则

本目录继承根级 [AGENTS.md](../AGENTS.md)，并补充运行时代码约束。

## 模块边界

- `game.js` 拥有世界状态、60 Hz 固定步更新、输入、AI、碰撞、音频、HUD、存档和 QA 状态。不要把游戏规则藏进渲染器。
- `renderer3d.js` 只负责把世界快照绘制成真实 WebGL 3D 场景。新增实体优先复用网格和缓冲，避免逐帧创建 GPU 资源。
- `i18n.js` 是玩家可见字符串的唯一目录。游戏数据保存稳定 ID/key，不保存翻译结果。

## 不可回归行为

- 战斗输入只改变移动方向；自动开火、自动超新星与自动救援继续由世界更新驱动。
- 单人 AI 与本地双人使用同一套战斗规则，AI 不得获得会掩盖玩家难度问题的无限耐久或无碰撞特权。
- 时间、冷却、生成和动画使用 `dt`；随机战役使用当前 run seed 的确定性随机源，UI/装饰性随机不得扰动玩法序列。
- 修改敌弹或生成参数时，先控制并发上限和可读性，再增加速度或数量；检查第一章 6 秒停火窗口及正常速度前 20 秒。
- Canvas HUD 保持 480×270 逻辑坐标，实际缓冲区按 CSS 尺寸与 DPR 扩展；3D 场景仍按质量和像素密度调整。

## 数据与验证

- 存档迁移必须通过默认值合并、合法 ID 白名单和数值钳制；不要无条件清空旧存档。
- 新 i18n key 同步 `zh`/`en`，动态 key 需让 `scripts/verify-localization.mjs` 可发现或显式登记。
- 为新关卡/构筑状态增加稳定的 `data-*` 诊断值，并确保 QA 开关只在本机地址生效。
- 完成后运行 `npm run verify`，再按[开发清单](../docs/DEVELOPMENT.md)检查受影响的实际玩法路径。
