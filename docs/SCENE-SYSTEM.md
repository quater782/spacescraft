# 场景系统与美术配置

## 当前原则（2026-09-25）

先确定一个主景的轮廓、位置与明暗，用星空和星云建立距离。九个星域不共用“行星 + 断环 + 碎片”的填充套餐。中间的战斗主体和危险弹体保持最高辨识度，科技感来自结构与局部能量，像素感来自真实几何阶梯与离散色面。调整背景不应改变战斗比例、碰撞、输入或自动技能。

## 唯一入口与职责

`renderer3d.js` 每帧只向 `SpaceEnvironment` 传入当前章节、世界快照和用户设置，再调用背景与目标两层绘制。环境不持有玩法状态，不通过给渲染器原型混入方法实现拆分。

| 文件 | 负责的内容 | 何时修改 |
| --- | --- | --- |
| [settings.js](../src/scene/settings.js) | 九生态场景色板、主景锚点、相机、灯光、雾、Bloom、星空、星云、三档预算 | 调整体风格与场景构图时先改这里 |
| [environment.js](../src/scene/environment.js) | 环境资源创建、色调过渡、镜头、灯光和绘制顺序 | 改层级或资源生命周期 |
| [scenery.js](../src/scene/scenery.js) | 主景几何、体素天体缓存 | 改具体形体与材质分区 |
| [events.js](../src/scene/events.js) | 战区过渡、异象/威胁诊断、星门、遭遇物件 | 改事件的可视表达 |
| [render-math.js](../src/render-math.js) | 无状态矩阵与颜色工具 | 共用数学，不放场景或游戏规则 |

背景与战斗共用既有几何/表面/粒子批次，通过显式 `paint` 接口调用。相机参数仅在配置中定义，Boss 登场与阶段仍不推拉镜头；遭遇演出、受限跟随与用户震动设置继续生效。

## 所有影响最终场景的输入审查

| 来源 | 实际影响 | 本轮处理/边界 |
| --- | --- | --- |
| `expedition.js` 的生态 ID、`game.js` 的当前章节 | 选用哪个场景 | 只按稳定 ID 解析；移除这两处废弃的 sky/haze/grid/star/landmark 配置 |
| `expedition.js` 的 accent/secondary | HUD、敌军模块的语义颜色 | 继续留在玩法目录；不再决定背景色板 |
| `profile.settings.quality`、窗口尺寸、设备 DPR | 分辨率、星数、星云数量 | 统一三档配置；尺寸/DPR 未变化时不重复调整渲染目标 |
| `world.time`、暂停、章节切换 | 视差、慢旋转、色调过渡 | 使用模拟时钟，暂停不推进；环境 RNG 独立且不消耗玩法序列 |
| `world.cinematic`、`world.shake`、玩家位置、`settings.shake` | 演出、震动、镜头跟随 | 统一归环境；保持原有 Boss 固定镜头规则 |
| `world.activeAnomaly` | 边缘光色与小幅亮度 | 移除无交互的异象实体，身份由环境光与 HUD 表达；力场、弹道和经济仍由模拟负责 |
| 战区/威胁定时器、路线选择、遭遇进度 | 临时提示和可交互物件 | 不再用中央白色方块做战区过渡；目标位置/进度仍读真实状态 |
| `render-surfaces.js`、`pixel-effects.js` 与渲染器的共用材质 | Toon 明暗、能量与粒子 | 保留共用材质和战斗语义；不为背景提高全局 Bloom |
| `game.js` 的 Canvas HUD 与 `settings.flashes` | 白闪、战区卡片、救援/任务提示 | 这是反馈覆盖层，继续由 HUD 所有；不是另一套场景绘制 |
| `style.css`、`index.html` | 视口尺寸、Canvas 层级、CRT 细线、菜单遮罩 | 保留外壳层，未把 UI 遮罩混入 WebGL 环境 |
| 本机 QA、菜单、模型/Boss 画廊 | 强制生态与纯模型视图 | 环境每帧隐藏所有缓存天体，只有活动场景重新启用；不暴露正式玩法写入口 |

已删除：废弃 `drawBiomeFeatures` 与花/树/珊瑚道具生成器、装饰性 `drawFlightCorridor`、重复的两路小景散布，以及 `game.js` 中不再显示的 2D 背景、地板网格、星空创建/固定步更新。没有保留供未来“回退”使用的第二套场景。

## 九星域的构图

| 星域 | 主景与组织 |
| --- | --- |
| sugarBloom | 双瓣收尖方舟，中央凹槽为暖琥珀色，外壳以冷钢灰为主 |
| crystalOrchard | 偏轴高低晶冠，以一高两低的节奏与暗基座形成方向性 |
| cometTide | 冷蓝体素行星与细轨道 |
| auroraFoundry | 单座断口轨道站，舱段/太阳能板服从同一个弧形轮廓 |
| thunderWorks | 大型断裂感应环，实体接头围绕暗核心组织 |
| cloudReef | 冷色地表天体 |
| eclipseCarnival | 远处暗天体与克制红色环带，不再叠加第二座遗迹 |
| prismGrave | 倾斜三碑与断拱，强调竖向负空间 |
| voidGarden | 裂环与分叉根状结构，青绿局部能量与暗紫主体分离 |

主景尺度不随质量下降；低档减少背景密度。天体只在行星/日蚀构图出现，不给所有生态机械添加一颗球。删除散落配景与其生成器；九类异象不再生成无交互实体，威胁状态不再画成悬浮信标。战斗物件仍读取真实碰撞、奖励或任务状态。

## 主景动态（2026-09-25）

动态细节附着在主景表面，单景采用 7–16 秒的光纹节奏，来自 `settings.js` 的 `motion`；星云漂移、轻微倾转与明暗呼吸采用 24 秒节奏。星云分布延伸到两侧远处，开启深度遮挡并放在主景后方，保持中央战斗留白。

- 方舟：本体有可见的缓慢偏航与侧倾，凹槽与壳面检修窗依次亮起。
- 晶冠：本体缓慢改变朝向，较宽的晶面反光逐段向上传递。
- 两颗行星：地表每秒约 2.8–3.2 度自转，真实 3D 阶梯云层以额外每秒约 4.9 度的角速度移动；云层透明度 0.56。云层一次创建并缓存，露出地表，不生成游离碎块。
- 轨道站：本体每秒约 3.7 度转动，弧形舱段运行灯依次传递，船坞内转轴及太阳能板随主结构运动；板片最大调角约 24 度。
- 感应环：外圈每秒约 8 度、内圈反向约 11 度旋转，灯带沿内圈实体逐段充能；移除原先快速明灭的电弧颜色切换。
- 日蚀：贴近环带的柔和流光缓慢移动。
- 断碑：本体缓慢偏航，凹刻槽内的光依次向上流动。
- 裂环：固定接头的微光与内外圈反向慢旋转。

所有动画读取模拟时间，暂停冻结；不使用显示帧率累积，不影响玩法随机序列。发光嵌件使用既有表面实例批次中的颜色，不随动画新建材质，不提高全局 Bloom。

## 资源与验证

星空/星云在初始化时创建，画质改变只调整绘制范围。体素天体按生态缓存，仅生成可见表面，当前三种天体构图最多三份；每帧先隐藏再按需要显示。基础几何/粒子仍复用已有批次。主景使用配置中的远景锚点，不进入互动深度。

`npm run verify` 包含场景配置、资源导入链、旧入口移除与原有游戏检查。`npm run smoke:biomes -- --scene-audit` 在九生态间轮换低/均衡/高画质，检查配置 ID、零丢弃、WebGL、帧率并生成截图；`--biome=sugarBloom` 可单独复核一张图。`--motion-audit` 额外保存各景八帧动态，检查相位推进、暂停冻结与零丢弃；`--motion-video` 为轨道站、彗潮行星和裂环保存 6.5 秒、24 FPS 的正常速度 WebGL 录像。动画可见度需要查看全尺寸画面/录像，不能仅以相位改变作为验收。事件抽查用 `smoke:anomalies`，模型与正常首章检查用 `smoke:models`。

新增诊断：`data-scene-profile`、`data-scene-quality`、`data-scene-layers`、`data-scene-config`、`data-scene-planet-cache`、`data-anomaly-presentation`、`data-scene-motion`、`data-scene-motion-phase`；原有材质、弹体和粒子诊断继续保留。历史 `data-celestial-scaffolding` 是兼容标记，当前实际构图以配置和 `data-scene-profile` 为准。
